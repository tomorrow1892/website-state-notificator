## 1. プロジェクトセットアップ

- [ ] 1.1 GitHub Actionsで実行する監視ワークフローと、GitHub Pagesでホスティングする静的UIの構成を決める
- [ ] 1.2 監視設定と状態を格納するJSONファイルの構造を定義する

## 2. 監視と状態永続化

- [ ] 2.1 複数監視対象の設定を読み込み、各対象にURL、判定ルール、複数LINE受信者、ポーリング頻度を扱えるようにする
- [ ] 2.2 GitHub ActionsからURLを取得し、通常文字列または正規表現で出現/消失の判定を実装する
- [ ] 2.3 前回の判定状態をJSONファイルに永続化し、次回実行時に比較できるようにする
- [ ] 2.4 判定ルールに従い、出現/消失の変化があった場合のみ通知対象とする

## 3. LINE通知

- [ ] 3.1 LINE Messaging APIを使った通知送信機能を実装する
- [ ] 3.2 通知メッセージにURL、判定ルール、前回状態、現在状態、検出時刻を含める
- [ ] 3.3 複数のLINE通知先をサポートし、各監視対象ごとに送信先を設定できるようにする

## 4. GitHub Actionsと運用

- [ ] 4.1 固定スケジュールのGitHub Actionsワークフローを設定し、監視対象全体を一括でチェックする方式を採用する
- [ ] 4.2 各監視対象のポーリング頻度設定をJSONに保持し、ワークフロー内で頻度判定を行う
- [ ] 4.3 失敗時のログ記録と、取得/通知エラー時に他の監視対象を継続処理するロジックを追加する
