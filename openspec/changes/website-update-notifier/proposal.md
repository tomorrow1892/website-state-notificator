## なぜ

手動でページを更新せずに重要な更新を検出し、LINEに素早く通知する仕組みが必要です。特に予約サイトの空き状況のように、変化が発生した瞬間に気づきたいケースで有効です。

## 変更内容

- GitHub Pagesを静的UIとして使い、監視設定の閲覧・編集を提供できるようにします。
- GitHub Actionsで定期実行し、指定されたURLを取得して変化を判定します。
- 監視設定を複数登録でき、各URLごとに複数のLINE受信者を指定できます。
- 変化判定は、消失・出現の両方に対応し、通常文字列と正規表現のいずれも設定可能にします。
- 監視データと状態はリポジトリ内のJSONファイルで保持し、テーブルやデータベースは使いません。
- 通知はLINE Messaging API経由で送信します。

## 機能

### 新しい機能
- `website-monitoring`: 複数の監視対象URLを扱い、各監視の判定ルールを柔軟に設定できる。
- `line-notification`: 監視対象の状態変化をLINEに通知する。

## 影響

- GitHub Pages上の静的UIと、GitHub Actionsによる定期実行の仕組みを導入します。
- 監視対象ごとのURL、判定ルール、通知先LINE ID、ポーリング頻度を設定する仕組みを追加します。
- 監視データはJSONファイルで管理します。
- LINE Messaging APIへのアクセスと、ページ取得・正規表現判定処理の依存関係が必要になります。
